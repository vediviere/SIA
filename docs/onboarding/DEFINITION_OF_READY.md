# Definition of Ready - SIA

## Objetivo

La Definition of Ready define las condiciones mínimas que debe cumplir una tarea antes de poder entrar a un sprint.

Su propósito es evitar que el equipo tome tareas ambiguas, incompletas o sin criterios claros.

## Regla general

Una tarea puede entrar al sprint únicamente si está suficientemente clara para que el desarrollador pueda trabajarla sin depender de suposiciones.

## Requisitos mínimos

Una tarea está Ready si cumple con lo siguiente:

1. Tiene una descripción clara.
2. Tiene un objetivo definido.
3. Tiene criterios de aceptación.
4. Tiene épica asignada.
5. Tiene alcance limitado.
6. Tiene responsable o frente responsable.
7. Tiene dependencias identificadas.
8. Tiene etiquetas relevantes.
9. Se sabe si es junior-friendly o senior-only.
10. No contradice reglas arquitectónicas.

## Tareas funcionales

Una tarea funcional debe indicar:

- Actor principal.
- Flujo de negocio relacionado.
- Resultado esperado.
- Reglas de negocio aplicables.
- Servicio o BFF involucrado, si ya se conoce.

## Tareas técnicas

Una tarea técnica debe indicar:

- Área afectada.
- Riesgo técnico si se implementa mal.
- Regla arquitectónica relacionada.
- Criterios técnicos de validación.

## Regla de entrada al sprint

Una tarea que no tenga criterios de aceptación no debe entrar al sprint.

## Excepción

Una tarea puede entrar como Spike cuando el objetivo sea investigar, aclarar o validar una decisión técnica o funcional.
